TASK 1: Add Shodan Integration (2-3 hours)

File to create: sentinelrecon/integrations/shodan_client.py

```python
import shodan
import logging
from dataclasses import dataclass
from typing import Optional

logger = logging.getLogger(__name__)

@dataclass
class ShodanData:
    ip: str
    hostnames: list
    org: str
    isp: str
    country: str
    ports: list
    cves: list
    last_update: str

class ShodanClient:
    def __init__(self, api_key: str):
        self.api = shodan.Shodan(api_key)
    
    def lookup(self, ip: str) -> Optional[ShodanData]:
        """Query Shodan for IP information"""
        try:
            host = self.api.host(ip)
            return ShodanData(
                ip=ip,
                hostnames=host.get('hostnames', []),
                org=host.get('org', 'N/A'),
                isp=host.get('isp', 'N/A'),
                country=host.get('country_code', 'N/A'),
                ports=host.get('ports', []),
                cves=host.get('vulns', []),
                last_update=host.get('last_update', 'N/A')
            )
        except Exception as e:
            logger.error(f"Shodan lookup failed for {ip}: {e}")
            return None
```

Requirements to add to requirements.txt:
  shodan==1.31.1

Setup:
  1. Get Shodan API key: https://account.shodan.io/
  2. Add to config: sentinelrecon config --set shodan_api_key YOUR_KEY
  3. Test: python -c "from shodan import Shodan; print('Shodan working')"

TASK 2: Add OTX Integration (2-3 hours)

File to create: sentinelrecon/integrations/otx_client.py

```python
import requests
import logging
from dataclasses import dataclass
from typing import Optional, Dict

logger = logging.getLogger(__name__)

@dataclass
class OTXThreat:
    indicator: str
    type: str
    reputation: int
    threat_details: Dict

class OTXClient:
    def __init__(self, api_key: str = None):
        self.base_url = "https://otx.alienvault.com/api/v1"
        self.api_key = api_key or ""  # OTX has free tier
        self.headers = {"X-OTX-API-KEY": self.api_key}
    
    def lookup_ip(self, ip: str) -> Optional[dict]:
        """Query OTX for IP threat intelligence"""
        try:
            url = f"{self.base_url}/indicators/IPv4/{ip}/general"
            response = requests.get(url, headers=self.headers, timeout=5)
            if response.status_code == 200:
                return response.json()
            return None
        except Exception as e:
            logger.error(f"OTX lookup failed for {ip}: {e}")
            return None
    
    def lookup_domain(self, domain: str) -> Optional[dict]:
        """Query OTX for domain threat intelligence"""
        try:
            url = f"{self.base_url}/indicators/domain/{domain}/general"
            response = requests.get(url, headers=self.headers, timeout=5)
            if response.status_code == 200:
                return response.json()
            return None
        except Exception as e:
            logger.error(f"OTX lookup failed for {domain}: {e}")
            return None
```

Setup:
  1. Get OTX API key (free): https://otx.alienvault.com/
  2. Add to config: sentinelrecon config --set otx_api_key YOUR_KEY
  3. Test: python -c "import requests; print('OTX working')"

Issue: "OTX lookup timeout"
Solution:
  1. Check internet connection
  2. Increase timeout in otx_client.py (currently 5 seconds)
  3. OTX API might be down (check status page)

Issue: "API key leaking in logs"
Solution:
  1. Check config_manager.py uses encryption (Fernet)
  2. Run: grep -r "shodan_api_key" output/  # Should be empty
  3. Update logging to exclude sensitive keys

════════════════════════════════════════════════════════════════════════════════════════════

When asked: "Tell me about a project you're proud of"

Answer:
  "I built SentinelRecon — a network reconnaissance toolkit that started as
   a simple port scanner. But I realized raw scan data isn't useful for beginners.
   
   So I added three layers:
   1. CVE intelligence: Every service is checked against NVD database
   2. Risk scoring: Weighted algorithm tells you what's critical
   3. AI explanations: Claude API explains findings like a mentor
   
   Then I realized scans are point-in-time. I added SQLite to track history.
   And recently, I integrated threat feeds — Shodan, VirusTotal, OTX, AbuseIPDB.
   
   Now when a scan finds an open port, users see:
   - What's running (service + version)
   - What's the risk (CVEs + risk score)
   - What's the context (threat intelligence, IP reputation)
   - What to do (AI-generated remediation steps)
   
   Latest version v1.5 just released with threat feeds. Next I'm adding cloud
   scanning (AWS/Azure/GCP) because that's where enterprises are moving.
   
   The project taught me full-stack security: network protocols, CVE databases,
   API integration, AI prompting, database design, and professional engineering
   practices."
